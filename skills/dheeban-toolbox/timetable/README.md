# محرك الجداول المدرسية (OR-Tools CP-SAT)

محرك عام في صندوق ذيبان، مجرَّب في 2026-11-27 بـ `ortools==9.15.6755` (Python 3.13). المصدر الرسمي: developers.google.com/optimization و github.com/google/or-tools.
**قاعدة:** كل مهمة جدولة أو فحص تعارض حصص تُنفَّذ بهذا المحرك، لا بحساب الذكاء الاصطناعي (أسرع وأوفر للرموز وأدق).

## التثبيت والتشغيل
```bash
bash setup.sh                                   # مرة لكل حاوية/خادم
PY=~/.dheeb/venv-ortools/bin/python
$PY engine.py solve    input.json out.json      # إنشاء / تحسين / إعادة جدولة جزئية
$PY engine.py check    input.json schedule.json # تعارضات جدول يدوي (فوري، بلا محرك)
$PY engine.py diagnose input.json               # لماذا تعذّر الجدول؟ (عربي + اقتراحات)
$PY -m unittest -v test_engine                  # 13 اختبارًا (طبيعية/معقدة/استثنائية/سرعة)
```
في مشروع: انسخ `engine.py` إلى المشروع (أو ثبّته حزمة) واكتب **محوّلًا** يقرأ من قاعدة بيانات المشروع الفعلية ويكتب النتيجة في جداوله الموجودة. المحرك لا يملك قاعدة بيانات.

## شكل المدخلات (JSON)
| المفتاح | المعنى |
|---|---|
| `days`، `periods_per_day` | الأيام (افتراضيًا الأحد–الخميس) وعدد الحصص |
| `teachers[]` | `id,name,max_weekly,min_weekly?,unavailable:[[يوم,حصة]],can_teach:[{subject,grades}]` |
| `classes[]` | `id,name,grade` · `students[]`: `id,class` (جدول الطالب = جدول فصله) |
| `subjects[]` | `id,name,max_per_day` |
| `requirements[]` | `class,subject,periods,teacher?` (teacher يثبت الإسناد) |
| `joint_groups[]` | تدريس متزامن: `id,classes,subject,topic,teacher?` — يُرفض إن اختلفت المرحلة أو غاب الموضوع أو اختلف عدد الحصص |
| `pinned[]` | `class,subject,teacher,day,period` حصص مثبتة إلزاميًا |
| `previous[]` + `partial.free_units` | إعادة جدولة جزئية: كل الحصص مقفلة إلا الوحدات المحررة (`فصل:مادة` أو `J:مجموعة`)، وما صار يخالف شرطًا جديدًا يُحرَّر تلقائيًا ويُذكر في `auto_freed_units` |
| `weights` | أوزان التفضيلات المرنة: `teacher_gap,class_gap,same_day_repeat,day_imbalance,change_from_previous` |
| `time_limit` | ثوانٍ قصوى للتحسين (الافتراضي 30) |

**إلزامي (لا يُتجاوز أبدًا):** لا تعارض معلم/فصل، التخصص والصفوف المصرح بها، النصاب، التوفر، عدد الحصص، الحد اليومي للمادة، الحصص المثبتة، ضوابط الدمج.
**مرن (يُحسَّن):** فراغات المعلمين والفصول، تكرار المادة في اليوم، توازن الأسبوع، أقل تغيير عن الجدول السابق.
التوقيت: `generated_at` بتوقيت Asia/Riyadh.

## المخرجات
`status` (OPTIMAL/FEASIBLE/INFEASIBLE)، `schedule[]`، `conflicts[]` (يجب أن تكون فارغة)، `stats` (الحصص والفراغات)، `seconds` و`first_solution_seconds`، و`diagnosis[]` عند التعذر: رسالة عربية تسمّي المعلم/المادة/الفصل/الشرط + `suggestions`. `views()` يعطي جدول كل معلم وفصل وطالب.

## التشخيص
1. فحص مسبق سريع: مادة بلا معلم مؤهل، معلم وحيد مؤهل يتجاوز نصابه أو توفره، فصل حصصه أكثر من الأسبوع، دمج مخالف.
2. إن لم يكفِ: نموذج بافتراضات لكل شرط إلزامي، و`SufficientAssumptionsForInfeasibility` يعيد أصغر مجموعة شروط متعارضة. المحرك لا يرخي أي شرط إلزامي تلقائيًا؛ الإدارة تختار الاقتراح.
